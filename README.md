# Выездной сервис коммунальной техники

Самостоятельный сайт и каталог запчастей, перенесённые с Tilda. Рабочий сайт использует PHP 8.3+ и собственную админку; GitHub Pages содержит отдельную статическую демонстрацию.

- Рабочий сайт: https://rkt1.ru/
- Админка: https://rkt1.ru/admin/
- Демонстрация: https://kibosh13.github.io/kommunal-tech-service/
- Основная ветка — `main`; статическая демонстрация — `gh-pages`.

## Возможности

В админке редактируются тексты пяти страниц, подписи, ссылки, изображения, PDF сертификатов, название компании и контакты. Товары можно добавлять, дублировать, удалять, сохранять как черновики и публиковать: название, артикул, марка, категория, цена, наличие, описание, характеристики и до 20 фотографий. Все опубликованные позиции автоматически включаются в общий каталог; каталоги HIDRO-MAK и KATMERCILER фильтруют соответствующую марку.

Заявки сохраняются вне публичного каталога хостинга. Есть статусы обработки и уведомления на настраиваемую почту. Поддерживаются PHP mail и SMTP с проверкой TLS-сертификата. Успешная отправка означает принятие письма транспортом, а не подтверждение доставки во «Входящие».

Метрика принимает стандартный код или номер счётчика. Из кода извлекается номер и генерируется известный скрипт Яндекса; произвольный JavaScript не исполняется. Вебмастер принимает метатег `yandex-verification` или его `content`. Индексация рабочего сайта включается отдельно; по умолчанию закрыта. Админка и статическая демонстрация всегда закрыты от индексации.

Каждое сохранение создаёт предыдущую версию контента (последние 30). Проверка версии защищает от потери изменений при работе в двух окнах. Копии контента не содержат заявки, пароли и SMTP-секреты. Удаляемые неиспользуемые загрузки перемещаются в приватный архив, исходные изображения и сертификаты защищены от удаления.

Инструкция для владельца: [docs/ADMIN.md](docs/ADMIN.md).

## Структура

| Путь | Назначение |
| --- | --- |
| `app/` | Валидация, хранение, серверный рендер, почта, шаблоны и начальный публичный контент |
| `admin/` | Интерфейс управления и вход |
| `api/admin.php` | Защищённые операции управления |
| `api/lead.php` | Приём заявок |
| `*.php`, `.htaccess` | Рабочие страницы; прежние адреса `*.html` сохраняются |
| `*.html`, `products.js` | Статический снимок для GitHub Pages, не рабочая база CMS |
| `assets/` | Изображения, шрифты и неизменённые сертификаты PDF |
| `uploads/` | Пользовательские загрузки, не включаются в Git |
| `tools/` | Локальный запуск, первичная активация и статический экспорт |
| `tests/integration.py` | Изолированные функциональные и защитные проверки |

## Локальный запуск

Нужны PHP 8.3+, расширения DOM, mbstring, fileinfo, GD и OpenSSL, а также Composer:

```sh
composer install --no-dev --prefer-dist --no-interaction
```

Подставьте свой абсолютный путь к приватной папке **вне корня сайта**:

```sh
RKT_STORAGE=/absolute/private/rkt1 php tools/provision.php
RKT_STORAGE=/absolute/private/rkt1 php -S 127.0.0.1:4183 -t . tools/router.php
```

Первая команда единожды выводит секретный код. Откройте `/admin/#setup=КОД` и задайте логин и пароль от 12 символов. Код действует семь дней, хранится только в виде SHA-256 и уничтожается после активации. Повторная инициализация не перезаписывает существующий доступ. Не публикуйте код или приватные файлы.

## PHP-хостинг

1. Установите зависимости Composer локально. Передавайте PHP-движок, `admin/`, `api/`, `app/`, необходимые файлы `vendor/`, публичные CSS/JS, `assets/`, `.user.ini`, `.htaccess` и защитный `uploads/.htaccess`. Не передавайте `.git`, тесты, инструменты, кэши и приватные данные.
2. Настройте HTTPS, PHP 8.3+ и `.htaccess`. По умолчанию хранилище создаётся рядом с корнем: для `/www/rkt1.ru` это `/www/rkt1-private`, не внутри сайта. Папка должна быть доступна PHP на запись и закрыта для HTTP.
3. Выполните первичную инициализацию единожды в отдельной приватной папке. Передайте её `auth.json` в приватное хранилище и сообщите владельцу одноразовую активацию по доверенному каналу.
4. Проверьте PHP-страницы и `api/admin.php?action=status` до переключения. Старые `index.html`, `hidromak.html`, `katmerciler.html`, `product.html`, `products.js` и `robots.txt` сохраните в непубличном архиве: Nginx может обслуживать существующие статические файлы до Apache. Затем проверьте прежние HTML-адреса и `robots.txt`.
5. При обновлениях передавайте только изменённые исходники. **Не перезаписывайте** хранилище, пользовательские `uploads/` и конфигурацию хостинга. Начальный `app/content.seed.json` используется до первого сохранения; рабочие правки находятся в приватном `content.json`.

Полный бэкап включает исходники, пользовательские `uploads/` и приватную папку вместе. Приватная папка содержит секреты и персональные данные: храните её копии с ограниченными правами, никогда не публикуйте на GitHub. Удалённые загрузки находятся в `media-trash/`; если восстановление старой версии требует такой файл, сначала верните его под исходным именем в `uploads/` через администратора хостинга.

## Почта

Получатель задаётся отдельно от контактной почты. Для отправителя используйте адрес обслуживаемого домена, для SMTP — реквизиты почтового ящика, не пароль FTP или REG.RU. SMTP-пароль находится только в приватном `mail-secret.json`, не возвращается через API. Пустое поле при сохранении сохраняет прежний пароль.

Исходный контент содержит выключенные уведомления. На рабочем хостинге включайте их после проверки транспорта и получателя. Даже при выключенной почте или ошибке отправки заявка сохраняется в админке. Проверьте «Входящие» и «Спам»; при необходимости настройте SMTP, SPF/DKIM/DMARC у почтового провайдера.

Владелец должен проверить текст согласия и выполнить применимые требования к обработке персональных данных; флажок сам по себе не подтверждает юридическую готовность сайта.

## Статическая демонстрация

```sh
php tools/export-static.php /absolute/path/to/static-demo
```

Экспорт переносит только публичные HTML/CSS/JS, изображения и документы. Второй необязательный аргумент — актуальный JSON контента из закрытого экспорта админки; храните его вне Git. Используемые пользовательские `uploads/` переносите отдельно только в составе согласованной публичной демонстрации.

GitHub Pages не выполняет PHP: там нет админки, сохранения правок, приёма заявок, уведомлений и Метрики. Формы обозначены как демонстрационные и ничего не отправляют. Все страницы имеют `noindex, nofollow`, `robots.txt` запрещает обход. Это указание для добросовестных поисковиков, а не ограничение доступа к публичному сайту.

Оплата, корзина, складской учёт и автоматическое обновление GitHub Pages из админки не реализованы. Сайт предназначен для запроса и подбора запчастей. Демонстрация обновляется отдельной публикацией экспорта. Неподтверждённые параметры и цены не вымышлены: исходные товары имеют стоимость «По запросу».

## Проверки

```sh
python3 tests/integration.py
composer audit --no-interaction
git diff --check
```

Тесты поднимают отдельный PHP-сервер, используют временные данные, случайный тестовый пароль и заглушку почты. Настоящие письма не отправляются; тестовые загрузки убираются после проверки. `RKT_TEST_MAIL=1` — исключительно тестовая заглушка, её нельзя задавать на рабочем хостинге.
